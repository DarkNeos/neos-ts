# YGOPro 编码库接入

项目统一使用 npm 发布版，具体版本由 `package-lock.json` 固定。

| 依赖                   | 当前用途                                             |
| ---------------------- | ---------------------------------------------------- |
| `ygopro-msg-encode`    | CTOS 发包、STOC 收包、对局消息读取及本地录像消息生成 |
| `ygopro-yrp3d-encode`  | YRP3D 读取与录制文件保存                             |
| `ygopro-yrp-encode`    | YRP/YRP2 结构、卡组与操作记录读取                    |
| `ygopro-deck-encode`   | YDK 导入、导出与网络卡组编码                         |
| `ygopro-lflist-encode` | 多段禁限表读取及服务器规则 hash                      |
| `koishipro-core.js`    | 浏览器 Worker 中的 YRP/YRP2 对局演算                 |

## 协议适配

UI 和服务层继续使用原有 protobuf 业务对象，由 `ocgAdapter` 转换库对象。
选择操作的响应值保留现有语义，CTOS 外层由库编码。网络分包不变。

历史 MSG_START 缺少 duelRule 时补齐后解析；MSG_SHUFFLE_SET_CARD 的服务器
布局在进入库前调整；MSG_REFRESH_DECK 和录像名字消息保留专用兼容处理。
库尚未支持的消息按原有 unimplemented 路径处理。

## 本地录像

匹配页可上传 `.yrp3d`、`.yrp` 和 `.yrp2`，也可独立提取卡组。
YRP/YRP2 的解压、校验与演算均在 Worker 中执行。关闭加载窗口会取消下载与演算。
文件读取、提取与播放由同一个回放导入会话管理。更换文件会取消旧任务，旧文件
的读取、进度、错误和卡组结果不会覆盖新文件；只有当前任务完成开局后才能跳转。
解压正文限制为 16 MB；卡组提取超时为 15 秒，演算超时为 120 秒。

首次演算需要卡库和约 14 MB 的 Lua 脚本包。脚本地址在两份 Neos 配置的
`localReplay.scripts` 中设置，按顺序尝试主、备用地址。已下载的卡库和脚本保存在
IndexedDB，24 小时内直接使用；过期后更新失败仍可使用旧缓存。
SQL.js 和对局内核的 WASM 随站点构建发布，与 npm 包版本保持一致。

卡库资源使用 `release` 和 `preRelease` 标识来源，不再依赖数组位置。
`CardSources` 统一管理加载完成的两份资源：展示资料按超先行 JSON 分类选择来源，
搜索保留两份来源，内核读取保持正式卡库优先。超先行 Lua 的需求单独按超先行
卡库中的类型判断，排除普通怪兽和衍生物，保留效果卡和普通灵摆卡。

超先行 Lua 的单文件目录配置在 `preReleaseResource.scripts`，当前使用
`https://cdn02.moecube.com:444/ygopro-super-pre/data/script/`。浏览页面、联机和
提取卡组不会下载这些脚本。仅在本地演算实际请求超先行卡脚本时，按文件下载并使用
相同的 IndexedDB 缓存；超先行脚本优先于正式 ZIP 中的同名文件。
出现超先行卡后，正式包中缺失的脚本依赖也按需补充，覆盖效果生成的卡片。
可选脚本的 404 也缓存 24 小时，必需的超先行卡脚本缺失则直接报错。

`preReleaseResource.version` 配置上游 `data/version.txt` 的地址。每次录像演算首次
需要超先行 Lua 时检查一次版本号，检查请求会重新验证浏览器 HTTP 缓存，最多等待
5 秒。同版本复用尚未过期的文件；版本变化后，旧文件和旧 404 缓存均需要刷新，
只下载本次演算实际用到的脚本，请求携带 `v=版本号`。缓存按脚本地址保存一份，
不会随着版本增长累积副本。每份文件单独记录成功下载时的版本号，下载失败继续
使用旧缓存，并在下次演算重试；版本检查失败或返回无效内容时沿用 24 小时缓存
策略。一次演算的后续依赖沿用首次检查的版本号，已加载的脚本不会中途替换。
浏览页面、联机和提取卡组不会触发版本检查。版本更新依赖上游发布时同步修改
`version.txt`，保留 24 小时过期刷新作为补充。

内核只能同步读取 Lua，因此发现新依赖后先结束当前演算，下载完成再按原种子和
操作记录重新演算，不输出缺少脚本时的中间结果。下载失败会显示文件名，关闭窗口
会终止 Worker 和下载。此流程只补充 Lua，不加载完整 `.ypk` 中的卡图和数据修订。

演算结果转换为 YRP3D，复用现有播放、定位、视角和卡组提取功能。YRP1 使用官方
客户端的 MT19937 初始种子转换，TAG 保留四位玩家与队友切换。
投降或断开造成操作记录结束时保留最后场面，不生成额外胜负结果。

历史录像仍依赖兼容的内核、卡库和脚本。缺失卡号、操作不匹配、脚本错误或超时
会显示原因，不能保证所有历史版本的录像都能由当前内核演算。

## 禁限表选择

编辑器提供可搜索的禁限表选择。OCG、TCG、408 的环境与所选表分别保存在全局编辑器偏好中，
下拉列表只展示对应环境的表。正式资源中带 TCG 标记的表归入 TCG，其余归入 OCG；
408 使用独立资源。旧版在 OCG 下选中的 TCG 表会迁移到 TCG 偏好。
切换后编辑区和搜索结果的角标同步更新。选择不阻止保存卡组或开始训练。
Side 页使用服务器发送的禁限表 hash，独立于编辑器偏好。

## 验证

`npm run test:unit` 包含格式边界、种子、发包长度、卡组顺序、禁限表和真实录像消息
业务结果校验。`tests/e2e/ygopro-codecs.spec.ts` 覆盖 YRP/YRP2 播放、TAG、资源缓存、
取消重试及禁限表偏好。协议交互另由 `duel-controls-regression.spec.ts` 和
`selection-dialogs.spec.ts` 覆盖。
`tests/e2e/pre-release-scripts.spec.ts` 使用真实 WASM 内核验证超先行脚本按需下载、
同名覆盖、辅助脚本、生成卡、版本更新、断网缓存、404 缓存过期、下载错误及取消重试。

`replay-import.test.ts` 验证文件读取和处理的先后顺序、取消、结果发布和启动资格；
`card-sources.test.ts` 验证卡号重叠时的来源规则、缺失来源和 Lua 需求。
`production-replay.spec.ts` 只通过上传和页面操作验证本地重演，可对预览构建和测试站运行。
